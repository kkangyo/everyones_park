# 겨울 공원 전체 레이아웃 — organic loop v1

사용자가 첨부한 공원 배치도의 **유기적인 외곽 순환로 / 중앙 원형 정원 / 북·남 연못 / 북서쪽 공연장 / 북동쪽 넓은 잔디 구역**을 겨울 게임 맵으로 재구성했다. 실제 지도를 정확한 축척으로 복제한 것이 아니라 기존 One Park의 보행·간식·벤치 기능에 맞춘 레이아웃 초안이다.

## 전체 구성

- [확대 가능한 SVG](winter-layout.svg), [순환로 강조/구역 번호 토글](review.html)
- [실제 게임 전체 화면](in-game-overview.png)
- [중앙 정원](in-game-garden.png), [공연장](in-game-stage.png), [연못](in-game-pond.png), [목교](in-game-bridge.png)

맵 저장 범위는 **144×176타일, 4,608×5,632px**이다. Tiled 좌표 배열은 직사각형이지만 실제 공원 경계는 여러 방향으로 들어가고 나오는 비정형 다각형이다. 바깥쪽 설경은 충돌로 막고, 내부의 구부러진 순환로와 넓은 설원·수목 군락을 구분했다. 기존 캐릭터/음식의 32px 규격은 바꾸지 않았다.

| 번호 | 구역 | 배치와 역할 |
| --- | --- | --- |
| 1 | 남쪽 입구 광장 | 접속 위치. 넓은 제설 광장과 양쪽 벤치, 북쪽으로 바로 진입하는 산책로 |
| 2 | 겨울 원형 정원 | 공원의 중심. 원형 순환로·8방향 방사형 보행로·눈 덮인 겨울 화단 |
| 3 | 북쪽 얼음 연못 | 동쪽의 큰 수경 공간. 서쪽 접근 산책로와 동쪽 호숫가 벤치 |
| 4 | 남쪽 얼음 연못 | 조용한 하부 연못. 수목 정원과 전망 언덕을 잇는 길 옆에 배치 |
| 5 | 야외 공연장 | 북서쪽 타원형 구역. 무대와 반원형 단차/계단, 별도 둘레 산책로 |
| 6 | 설원 놀이마당 | 참고 이미지의 북동쪽 운동장 위치에 대응하는 넓은 겨울 잔디 구역. 둘레를 걷거나 안쪽 눈밭에 진입 가능 |
| 7 | 겨울 수목 정원 | 남서쪽 작은 순환로. 소나무 군락·중앙 쉼터·벤치 |
| 8 | 연못 전망 언덕 | 동쪽 가장자리의 높이를 암시하는 지형과 난간. 두 연못/개울을 바라보는 쉼터 |
| 9 | 소나무 숲길 | 서쪽의 굽은 보조 산책로. 열린 정원과 숲 사이를 잇는 조용한 동선 |
| 10 | 얼음 개울 목교 | 두 연못을 잇는 좁은 얼음 개울 위의 보행 교량. 중앙에서 전망 언덕으로 가는 지름길 |

## 동선과 겨울 처리

주 순환로는 18개 제어점을 부드럽게 연결한 **폭 5타일**의 곡선이다. 공연장/설원/수목 정원에는 작은 보조 순환로가 있고, 중앙 정원의 방사형 길과 입구 직통길, 연못 사이 목교가 긴 우회를 줄인다. 접근 가능한 눈밭도 걸을 수 있으며 화단·나무·난간·얼음은 통과할 수 없다.

연못과 개울은 얼어붙은 색/질감으로 표현했지만 보행 구역은 아니다. 목교 24타일만 얼음 위를 건너는 통로로 열었다. 뒤에 그린 일반 산책로가 목교 재질을 덮어쓰지 않도록 생성 순서를 보정했다.

간식 트럭은 **기존 8개 ID/메뉴를 유지**했다. 남쪽 입구 주변 2대, 중앙 정원 남서쪽 2대, 수목 정원·공연장 아래·연못 북측·전망 언덕 남측에 각 1대씩 배치했다. 별도 작은 포장 쉼터에서 주문할 수 있게 했고, 주 산책로 전체를 막지 않도록 접근 공간을 비웠다. 벤치는 **22개 / 44석**으로 나누어 정원·호숫가·공연장·입구·숲길에 배치했다.

바닥과 식재는 기존 픽셀 타일을 기반으로 한 **배치 검토용 그래픽**이다. 최종 건축물/가로등/난간 코너/곡선 경계 전용 타일 등 상세 아트는 별도 제작할 수 있다. 수목 가장자리는 나무 밑동 충돌과 2타일 높이 스프라이트의 앞뒤 정렬을 그대로 사용한다.

## 구현 위치

- `assets/maps/park.json`: 클라이언트와 서버가 읽는 실제 새 맵. ground/obstacles/spawns/trucks/seats 구조 유지.
- `scripts/lib/winter-park-layout.ts`: 외곽선, 주요 구역, 곡선 순환로, 연못, 트럭/벤치 위치, 수목/화단 배치의 단일 원본. 고정 시드로 재생성.
- `scripts/gen-placeholder-map.ts`: Tiled JSON과 16칸 타일셋 출력. 기존 타일 ID를 유지하고 비어 있던 13–15번에 겨울 화단/목교/공연장 단차를 추가.
- `assets/tiles/placeholder.png`: 256×64 타일셋. 기존 32px 타일·8열×2행 구조 유지.
- `landmarks` 오브젝트 레이어: 구역 이름/중심/접근 좌표. 서버·클라이언트의 기존 로더는 추가 레이어를 무시하며 기존 기능을 그대로 읽는다. 향후 미니맵/구역 안내용으로 쓸 수 있다.

기존 JSON을 손으로 고치는 대신 배치 원본을 수정하고 재생성한다. Tiled에서 직접 편집하기 시작하면 생성기를 실행할 때 편집 결과가 덮어써진다는 점을 유의한다.

```bash
pnpm gen:map
pnpm preview:map
pnpm check:map
```

`preview:map`은 실제 저장된 park.json의 타일/트럭을 그려 `winter-overview.png`, `winter-layout.svg`, `review.html`을 만든다. 별도의 가상 설계도를 보여 주는 것이 아니다. `winter-layout.png`와 게임 화면 캡처는 Chromium 검토 도구 `scripts/review-park-browser.cjs`로 만들었다. 이 도구는 Playwright/Chromium이 있는 검토 환경에서 임시 개발 서버에 접속해 실행하며 게임 의존성은 추가하지 않았다.

## 검증

- [충돌/동선 검사 결과](check-report.json), [실행 로그](check.log)
- [실제 브라우저/게임 접속 결과](browser-check.json)
- 생성 결과를 두 번 비교해 지면/장애물의 결정적 재현을 확인했다.
- 입구에서 **트럭 8개 주문 지점 + 벤치 44개 일어서기/앉기 접근 지점 + 구역 10개 접근 지점 = 62개 경로**를 런타임 공통 A*로 확인했다. 경로 선분도 실제 12×6px 발 충돌 상자로 검사했다.
- 18개 주 순환로 구간을 포장된 길만 사용하는 격자에서 검사해 연결과 과도한 우회가 없음을 확인했다.
- 보행 가능한 14,086타일 모두 입구와 연결되어 있다. 막힌 수목 사이에 생긴 작은 접근 불가 틈은 식재로 닫았다.
- 얼음 1,218타일은 모두 충돌 처리, 목교 24타일은 보행 가능. 맵 외곽으로 빠져나가는 열린 가장자리 없음.
- `pnpm typecheck`, `pnpm build`, 새 지도 생성/미리보기/검사 스크립트의 strict TypeScript 검사 통과.
- 격리된 임시 서버에서 실제 계정 생성/채널 입장 후 새 크기·8개 트럭·22개 벤치·10개 구역 레이어를 로드했다. 페이지 오류·실패한 에셋 요청 없음.

운영 서버 배포/재시작은 수행하지 않았다. 실행 중인 게임 서버는 맵을 메모리에 보관하므로 새 맵을 적용할 때 서버를 재시작하고 클라이언트도 새로고침해야 같은 배치/충돌을 사용한다. 현재 구현은 눈으로 덮인 지형/얼음/나무의 겨울 표현이며, 날씨 파티클이나 BGM 기능은 이번 레이아웃 작업에 포함하지 않았다.
